# Attic Minecraft Launcher v0.0.12 — 隐性 bug 审计轮：退出不再留孤儿、保存不再丢数据、微软登录更抗抖（试装轨 prerelease）

专注远古 Minecraft（Pre-Classic → b1.7.3/1.5.2 区间）的桌面启动器。本版为 v0.0.11 的增量试装版，内容是一轮**只读代码审计产出的高+中危 10 条隐性 bug 修复**——「隐性」= 正常路径全部工作正常、测试全绿，只在特定触发条件（进程崩溃、文件被杀软锁定、网络瞬时抖动、下载中断、连点按钮）下才出错的那类缺陷。**静默自动更新通道自 0.1.0 stable 起才开放**，0.0.x 用户请从 Releases 页手动下载新版安装器，覆盖安装即升级（数据 `.attic` 原样保留）。构件矩阵与壳定位同 v0.0.2–v0.0.11（见对应页说明）。

## 壳层与进程管理

- **游戏进程不再被截成孤儿**：Tauri 壳退出、Electron 壳崩溃这两条路径原先都会在「通知游戏进程退出」真正发出前就硬退，游戏进程残留在任务管理器——本版两条路径均改为先收敛再退。
- **停止按钮连点不假死**：并发两次「停止」原先互相覆盖等待句柄，其中一次的 await 永不返回（表现为界面卡在停止中）；现共享同一条退出等待。
- **看门狗不可用不炸启动器**：窗口看门狗依赖的 powershell 若被系统精简或安全策略拦截，原先会把启动器主进程整体击穿；现降级为「关窗后进程残留」旧行为并记录原因。

## 数据安全

- **实例档案/全局配置在文件被瞬时锁定（杀软扫描等）时不再静默丢数据**：合并写回原先允许「读失败 = 当空文件」，随后整档覆盖会把 Betacraft v1 遗留键（代理/保窗/RPC 等）悄悄抹掉；现读失败直接报错拒写，宁可失败一次也不丢键。
- **账户文件原子写 + 坏文件不吞**：accounts.json 写入改为临时文件原子替换（断电/强杀不再留半截）；文件损坏时显式报错并提示修复，不再静默显示「无账户」并在下次保存时把空清单固化成全账户丢失。

## 微软账户登录

- **设备码授权窗口期抗网络抖动**：登录等待期间一次瞬时网络错误原先直接中止整个授权流程（用户得从头再来）；现按轮询间隔自动重试，连续 5 次失败才放弃。
- **不再误报「未购买游戏」**：档案接口瞬时故障（限流/服务抖动/令牌过期）原先一律被说成「此账户没有 Minecraft」；现仅真正的 404 才报未购买，其余归因内部错误。
- **并发刷新不再互踩**：启动自动刷新与手动刷新同时发生时，同一刷新令牌被双刷可能触发微软的重放检测、吊销整个令牌族（此后登录全部失效）；现按账户去重，并发调用共享同一次刷新。

## 供给链自愈

- **原生库半截文件自动修复**：下载中断/磁盘满留下的半截 natives 文件原先「存在即跳过」，导致每次启动都报缺原生库且无法自愈；现按大小校验、不符自动重解，写入也改为原子落盘。
- **Java 自动供给失败不留半套**：Zulu JDK 下载/解压失败残留的残缺目录原先会被缓存命中、把坏 java 路径当已装返回；现失败即清理，下次走全新下载。
- **基础库集完整性闸门收紧**：depends 解包遇不支持的压缩格式原先静默跳过后照常登记版本号（半套库集恒过检查）；现直接报错中断、不登记，下次启动重试。
